# Review 2 — progression, gamification, and scope

Re-read the vision, rank table, economy requirements, device/vehicle ladder, and production dependencies after review 1. Tested the early purchase path on paper and challenged each unlock with “what new decision does this introduce?”

| Finding | Applied refinement |
|---|---|
| Lifetime collection did not itself guarantee enough available cash for the first fixed camera | Added an exact three-shift tutorial ledger, ending with a bought camera and 180 cr reserve; disclosed the scripted tutorial payments |
| The loan-camera fallback could be sold or retained accidentally | Defined one funded demonstration shift, non-saleable status, and exclusion from challenges |
| Road access and cars had unlocks but incomplete purchase proposals | Added permit prices, car prices, early tyres/engine upgrades, and upkeep disclosure |
| “Active work keeps cash moving while overloaded” ignored shared administration | Replaced that claim with surveying, better evidence, and capacity decisions |
| Idle clean shifts could reduce anger without any work | Required five valid processed cases and no eligible expiry/incident for the clean-shift benefit |
| The first slice promised driving but the only driving task came afterward | Added T06A for a basic car; T09 now adds upgrades and bounded pursuit |
| Later staff and devices needed meaningful operating differences | Added supervisor/technician costs, trailer setup/capacity, section-pair upkeep, and patrol-module operations |
| Post-automation play risked becoming passive waiting | Added a chosen shift intention, purchase goal tracking, causal yield history, and distinct questions for each tool |

The core progression can now be implemented without inventing the first-camera purchase path or car-task dependency. Longer campaign timing remains provisional; the current simulator does not model purchase policies or the 25,000 cr target.

Scope remains intentionally staged: aiming and placement first, driving support in the slice, richer pursuit and friends exchange next, then section/border/politics. All requested features remain in the full plan; none is falsely marked implemented.
